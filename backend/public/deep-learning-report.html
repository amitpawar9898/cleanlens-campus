AI visual inspection for fruit, vegetables, and visible food waste in the SIT CleanLens campus cleanliness workflow.

Implementation report · model-specific performance not yet measured

Project summary

CleanLens lets a user submit an inspection photo, runs an on-device object detector, displays detected objects and bounding boxes, and stores the inspection result with its image and selected campus location. When configured by the server, optional Gemini vision assistance can supplement incomplete local detections.

Detection pipeline

  1. The selected image is resized for browser inference and prepared as a 640 × 640 model input.
  2. YOLO returns object class scores and box coordinates. The app decodes supported channel-first and row-oriented output tensors, applies a configurable confidence threshold and class-aware non-maximum suppression, and draws the surviving boxes.
  3. Each local object is shown with its class, location in the image, and detector score. The stock model does not determine freshness; condition is shown as uncertain unless a configured vision provider supplies a visual estimate.
  4. When server-side Gemini is configured and cloud assistance is enabled, the backend can request structured object labels, visible-condition estimates, and normalized image boxes. Cloud confidence is not presented as a measured detector score.
  5. The inspection API saves the result, object list, image, building/area, and processing metadata. Students can view their own inspection history; authorized reviewers handle formal findings.

Model and data status

The bundled yolo11n.onnx is a general COCO model. It can recognize some everyday classes such as apple, banana, orange, broccoli, and carrot. It is not trained for every local fruit, campus litter, decomposition, or mould. A class name added in settings does not teach the model that class.

No project-specific training dataset or measured evaluation results are included. Therefore this report does not claim precision, recall, mAP, or reliable spoilage classification for CleanLens. Values must be measured after collecting and annotating a representative dataset.

Training and evaluation plan

  • Gather images for each target fruit, vegetable, and waste class across lighting, camera, distance, background, and clutter variations.
  • Annotate object bounding boxes and split by scene/source into training, validation, and held-out test sets to reduce data leakage.
  • Train and export using the repository workflow in backend/ml/README.md and backend/ml/train_export.py.
  • Report precision, recall, mAP@0.5, and mAP@0.5:0.95 on the held-out test set, plus per-class results and failure examples.
  • Evaluate freshness estimation separately against human-reviewed labels. Visual appearance alone must not be presented as a food-safety determination.

The training workflow writes a separate ONNX model; it does not overwrite the bundled model automatically.

Privacy and limitations

Local detection stays in the browser. If cloud assistance is enabled, inspection images may be sent to the configured Gemini provider when local results appear incomplete, unless server settings force verification. Keep provider credentials in backend environment variables. Detection can miss objects or mislabel visually similar items; review results before creating a complaint.
